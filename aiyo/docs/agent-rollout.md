# AI 行程修改預覽：分流與觀測

`AGENT_PREVIEW_ROLLOUT_PERCENT` 控制**建立新預覽**的使用者比例，預設 `100`。設定 `0` 可停止建立新預覽；設定 `1`–`99` 時，以登入使用者 ID 的穩定雜湊分桶，同一使用者不會在請求之間隨機切換。無效設定會關閉新預覽。變更環境變數後須重新啟動 app 服務。

已建立的預覽仍可確認或取消；已提交的修改仍可復原或重做，避免調低比例時留下不能處理的資料。未進入分流的使用者嘗試修改現有行程時，預覽 API 回 `503 feature_unavailable`，畫面會提示暫時無法產生預覽，不會暗中直接改動行程。

預覽建立與套用 API 每次回應都寫一筆 `[agent-api]` 結構化日誌，只有 `operation`、HTTP `status`、`durationMs`，不記錄使用者 ID、指令或行程內容。可從容器日誌依操作和狀態碼計算呼叫量、錯誤率、延遲分位數；`409` 是版本競爭，`422` 是驗證拒絕，須與 `5xx` 服務失敗分開觀察。小流量啟用前後應固定量測同一組操作案例並保存比較結果；若服務錯誤或延遲超出部署環境的基線，將比例降回 `0` 並檢查日誌及資料庫 mutation 狀態。

可用 `docker logs --since 1h aiyo-new-app-dev 2>&1 | node scripts/summarize-agent-api-logs.mjs` 計算每種操作的呼叫量、狀態碼、服務失敗比例與 p50／p95 延遲。統計只包含有 `[agent-api]` 標記的請求；開啟正式流量前應保存一份基線，觀察窗口須有足夠樣本，不能以單次成功推定穩定性。

這個開關不取代模型品質驗證。地點查核、權限、revision CAS、預覽確認與 undo/redo 的既有測試仍是啟用門檻。

## 預覽中的人工調整

使用者可在套用前修改單一操作的開始時間，或輸入地名要求重新查證並替換地點。地點替換會在行程目的地範圍內解析，查證成功後重新計算整份預覽；畫面顯示供應來源與查核時間。無法確認座標或地點時回傳錯誤，不會用猜測結果填入。調整和套用均檢查編輯權限、預覽狀態及行程版本，避免覆蓋較新的修改。

目前排程驗證會拒絕同一天、同一開始時間的重複項目，以及新增、替換或搬移造成的時間倒序。搬移時可指定新時間，預覽中也可再調整。地點或相鄰路段改變時，預覽會清除不再適用的舊交通時間和距離估算。步行、單車與開車路段會向地圖服務重查；若路程本身超過兩站開始時間間隔就拒絕預覽，緩衝少於十分鐘則顯示警告。路線查詢失敗時明示待確認。Overpass 的 `opening_hours` 可由精確地名解析帶入預覽；`24/7` 或每日固定單一時段可判斷開始時間是否落在營業範圍，關門前三十分鐘內提示停留時間待確認。含星期、國定假日或多段時窗的規則在行程尚未保存旅行日期前不推斷開門狀態。大眾運輸與完整停留時長仍須在預覽中人工核對；正式擴大分流前應補齊日期模型及相應固定案例。
